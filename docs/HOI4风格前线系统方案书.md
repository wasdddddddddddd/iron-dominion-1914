# Iron & Dominion 1914 — 钢铁雄心风格前线系统方案书

> 目标：实现类似 HOI4 的连续战线系统——自动生成战线、均分兵力、动态推进、防御加成。

---

## 一、与当前系统的本质差异

| 维度 | 当前系统 | HOI4 风格系统 |
|------|----------|--------------|
| 兵力分布 | 集团军聚在单个城市 | 沿整条战线均匀展开 |
| 边境概念 | 单个"前线城市"判定 | 一段连续的战线 |
| 防御覆盖 | 每个城市独立守军 | 战线全覆盖，无空隙 |
| 突破行为 | 集团军打一个城 | 多段同时推进或单点突破 |
| 视觉表现 | 看不到战线 | 地图上可见战线（红色/蓝色） |

## 二、战线生成算法

### 2.1 输入
- 两个交战国家 A 和 B
- 所有省份的归属、中心坐标、邻接表

### 2.2 步骤

```
Step 1: 找边境省份
  遍历 A 的所有省份 P_A
  遍历 P_A 的每个邻接省份 P_adj（通过 PROVINCE_ADJ）
  如果 P_adj 属于 B → 记录 P_A 和 P_adj 是一对边境省份

Step 2: 找边境线段
  对每对边境省份，找它们共有的边界线段
  使用省份的多边形数据（province.r[]），求两个多边形的交集边
  
  简化方案（因为没有详细的边界几何数据）：
  用两个省份的中心连线中点和法向量近似边界线段
  → 取两个省中心的中点 M = ((Ax+Bx)/2, (Ay+By)/2)
  → 过 M 做垂直于 AB 连线的线段（长度 ≈ 0.5°）

Step 3: 排序连接
  把所有边界线段按地理位置排序（从左到右/从上到下）
  相邻的线段连接起来，形成一条或多条连续的战线

Step 4: 分割战线段
  将战线按 3°~5° 长度均分为 N 段
  N = max(2, 总长度 / 4°)
  每段分配兵力比例 = 段长度 / 总长度
```

### 2.3 示例（德法边境 1914）

```
德国省份: 亚琛(6.1,50.8), 科隆(6.9,50.9), 特里尔(6.6,49.8), 
          梅斯(6.2,49.1), 斯特拉斯堡(7.7,48.6)
法国省份: 色当(4.9,49.7), 凡尔登(5.4,49.2), 南锡(6.2,48.7),
          埃皮纳勒(6.5,48.2), 贝尔福(6.8,47.6)

战线从 (6.1,50.8) 经 (5.5,49.5) 到 (6.8,47.6)
总长约 5°，分 3 段，每段约 1.7°
```

## 三、战线数据结构

```javascript
// 全局：G._frontlines[country] = Frontline[]
// 每个战线对象：
{
  id: 'fl_10001',
  myCountry: 'GERMANY',
  enemyCountry: 'FRANCE',
  theater: 'WESTERN',
  
  // 战线几何：Array of {lon, lat}
  polyline: [
    {lon:6.1, lat:50.8},  // 北端点
    {lon:5.5, lat:49.5},  // 中间点
    {lon:6.8, lat:47.6}   // 南端点
  ],
  
  // 战线分段：Array of Segment
  segments: [
    {
      id: 'seg_1',
      startLon: 6.1, startLat: 50.8,
      endLon: 5.8, endLat: 50.15,
      length: 1.7,                        // 段长度(度)
      assignedGroupId: 'ag_1001',         // 分配的集团军
      myStrength: 5,                      // 己方在该段的师团数
      enemyStrength: 3,                   // 敌方在该段的师团数
      tension: 0.6,                       // 紧张度（0~1，敌越多越紧张）
      planningBonus: 0,                   // 计划加成（0~100%）
    },
    // ... 更多段
  ],
  
  lastRecalc: G.tick,  // 上次重算的 tick
}
```

## 四、战线可视化（地图渲染）

### 4.1 Canvas 绘制

```javascript
function drawFrontlines(ctx) {
    for (let co in G._frontlines) {
        for (let fl of G._frontlines[co]) {
            // 画主线（粗，半透明，国家颜色）
            ctx.strokeStyle = getCountryColor(fl.myCountry) + '80'; // 半透明
            ctx.lineWidth = 3;
            drawPolyline(ctx, fl.polyline);
            
            // 画分段线（细，不同透明度表示紧张度）
            for (let seg of fl.segments) {
                ctx.strokeStyle = getHighlightColor(seg.tension);
                ctx.lineWidth = 2;
                drawSegment(ctx, seg);
                
                // 标注分队兵力
                drawLabel(ctx, seg.midLon, seg.midLat, seg.myStrength + ' div');
            }
        }
    }
}
```

### 4.2 颜色约定
- 己方战线：绿色（低紧张）→ 橙色（中）→ 红色（高紧张，敌多）
- 敌方战线：灰色
- 沿战线圈：圆角连接各段

## 五、兵力分配算法

### 5.1 基本分配

```
输入：一条战线 + N 个己方师团
输出：每个师团在战线上的站位

算法：
  1. 计算战线总长度 L
  2. 计算每段需要的师团数 = N × (段长度 / L)
  3. 按紧张度（tension）调整：
     - 高紧张段（tension > 0.7）→ 师团数 × 1.5
     - 低紧张段（tension < 0.3）→ 师团数 × 0.5
  4. 确保总和 = N（用四舍五入填补误差）
  5. 每个师团站位 = 沿段均匀分布
```

### 5.2 特殊兵种分配
- **火炮**：放置在段后方 1°~2°，覆盖整段战线
- **骑兵**：分配到 tension 最低的段（薄弱处，便于突破）
- **工兵**：分配到 tension 最高的段（加固防线）

## 六、计划加成系统（Planning Bonus）

HOI4 的核心机制：单位在前线"准备"越久，进攻时加成越高。

### 6.1 规则

```
每个战线段的 planningBonus：0% ~ 100%

积累速度：
  + 3%/tick   ← 战线后方，未交战
  + 1%/tick   ← 战线前沿，有小规模交火
  + 0%/tick   ← 正在大规模交战中
  - 5%/tick   ← 战线段被敌军突破

撤退后归零。

加成效果：
  - 进攻时：单位伤害 +planningBonus%
  - 攻城时：城市掉血速度 × (1 + planningBonus)
  - 防守时：单位受到伤害 -planningBonus/2%
```

### 6.2 使用时机

计划加成在主攻（总攻阶段）时一次性释放：
- 累积 80% 计划加成 → 发动总攻 → 加成在战斗结束后清零
- 未发动总攻 → 加成继续积累

## 七、战线动态变化

### 7.1 省份易主触发重算

```
当任一交战国的省份归属变化：
  1. 标记战线为 dirty
  2. 下个 tick 重算战线几何
  3. 重新分配分段和兵力
  4. 规划加成保留 50%（战线推进太快，重新侦察）
```

### 7.2 战线推进

```
当集团军攻克一个敌方城市（城市 HP = 0 + owner 改变）：
  1. 该城市和对应省份归属进攻方
  2. 触发战线重算
  3. 战线向前推进，position 更新
  4. 单位自动沿新战线重新部署
```

### 7.3 被突破处理

```
如果某段战线 tension > 0.9（敌我兵力比 > 3:1）：
  1. 该段标记为 breached
  2. 从相邻段抽调 20% 兵力增援
  3. 如果仍然失守 → 战线后撤到下一排省份
```

## 八、与集团军系统的整合

### 8.1 集团军 → 战线映射

```
OFFENSIVE 集团军：
  → 战线前端（最接近敌国的段）
  → 负责执行突破、攻城
  → 积累 planningBonus

DEFENSIVE 集团军：
  → 战线全段均匀分布
  → 不主动进攻，只防守
  → 计划加成用于防守减伤

RESERVE 集团军：
  → 战线后方 3°~5°
  → 被突破时快速增援 breached 段
```

### 8.2 执行流程（每 tick）

```
1. 战线几何更新（20 tick 一次）
   for each 战线:
     重新计算 polyline 和 segments
     更新每段 myStrength / enemyStrength / tension

2. 兵力分配（20 tick 一次）
   for each 战线:
     按段分配集团军成员
     移动单位到段的站位坐标

3. 计划加成更新（每 tick）
   for each segment:
     根据交战状态更新 planningBonus

4. 推进/后撤（省份易主时触发）
   if province changed owner:
     重新计算所有相关战线
```

**结论**：这个系统解决的核心问题是"军队应该覆盖整条国境线，而非只蹲在几个城市里"。HOI4 证明了这个思路在战略游戏中的有效性——战线系统让 AI 的行为看起来更像一个"军事指挥"，而不是几十个独立行动的散兵。
